# FileEncryptor

> 🔐 轻量级文件加密工具 | Windows GUI + CLI | 基于 AES-256-GCM
> Windows 文件加密工具，提供图形界面 (Win32) 和命令行 (CLI) 两种版本。

基于 AES-256-GCM 与 PBKDF2-HMAC-SHA256 的流式文件加解密工具。支持大文件分块处理，并提供简洁安全的操作方式。

## ✨ 功能特性 (通用)

* **认证加密**：AES-256-GCM + PBKDF2-HMAC-SHA256 密钥派生，密文自带认证标签，密码错误或文件被篡改都能被可靠检出
* **大文件支持**：流式分块加/解密，内存占用低
* **安全删除**：独立功能，可用随机数据覆写 1-3 次后再删除（按钮 / 拖放 / 右键菜单 / 命令行四种入口）；删除文件夹时连同目录一起清掉
* **可选删除策略**：加密后按设置保留或覆写删除源文件；解密后可直接删除加密文件
* **零第三方依赖**：密码学全部使用 Windows 自带的 CNG（bcrypt），无需安装或随包携带 OpenSSL
* **格式互通**：GUI 与 CLI 使用完全相同的文件格式，可互相解密

> **平台说明**：本工具**仅支持 Windows**。
> 早期版本曾通过 OpenSSL 支持 Linux / macOS，但不同平台上的 OpenSSL 构建本身就可能存在差异，
> 同样会导致"同一份密文换个平台解不开"的漂移风险，因此最终选择**只保留 Windows CNG 一套实现**。
> 加密算法与文件格式都是标准的，密文本身与平台无关，只是**没有在其他平台上编译验证过**。

## 🔐 加密算法与文件格式

| 项目 | 说明 |
|---|---|
| 加密算法 | AES-256-GCM（认证加密 / AEAD） |
| 密钥派生 | PBKDF2-HMAC-SHA256，迭代次数可选 |
| 加密强度 | 快速 150,000 / 标准 300,000（默认）/ 安全 450,000 / 极强 600,000 |
| 随机数 | Windows CNG `BCryptGenRandom`（salt 16 字节，IV 12 字节） |

文件格式（v3，当前版本）。**两个槽位完全对称**，头部没有任何字段标明哪个是真：

```
偏移 0    魔数[8]        "FENC\r\n\x1a\n"   用于与旧格式区分
偏移 8    版本[1]        = 3
偏移 9    标志[1]        bit0 启用防暴力破解, bit1 模式(0=永久删除, 1=限时锁定)
偏移 10   迭代次数[4]    PBKDF2 迭代次数（小端）
偏移 14   最大尝试次数[2]
偏移 16   锁定天数[2]
偏移 18   saltA[16]
偏移 34   IV_A[12]       GCM 推荐 96-bit nonce
偏移 46   验证标签A[8]
偏移 54   槽A密文长度[8]  小端
偏移 62   saltB[16]
偏移 78   IV_B[12]
偏移 90   验证标签B[8]
偏移 98   剩余次数[2]    ← 可变（不参与认证）
偏移 100  锁定截止[8]    ← 可变（Unix 秒，0 = 未锁定）
偏移 108  密文A[槽A密文长度]
随后      密文B（直到文件末尾）
```

> **偏移 8~98 作为 GCM 的 AAD 参与认证**：两槽的 salt / IV / 验证标签、迭代次数与保护策略
> 一旦被改动，解密会直接认证失败，因此攻击者无法通过篡改文件头来关闭保护或替换某个槽。
> 偏移 98~108 需要在没有正确密码时也能改写，故不参与认证（能力边界见下文「防暴力破解」）。

> 迭代次数写在文件头里，**解密时自动读取**，因此调高加密强度不会影响旧文件的解密。

**两个槽位是对称的，且随机分配**：

* 头部**没有**任何字段标明哪个槽是真、是否存在诱饵
* 加密时**随机决定**真实载荷进哪个槽，消除「真文件永远在 A」这类统计特征
* 没有诱饵时照样写满两个槽，另一槽填随机数据（长度取真实密文的 50%~150%），
  所以**连"有没有藏第二份"都无法从文件判断**
* 代价：**文件体积始终约为明文的 2 倍**

**格式支持**：

* 程序**只支持 v3 格式**（即上表），不再读取历史格式（v2 / v1 / 最旧的 CBC）
* 版本号字段保留在文件头中以便将来演进，但当前只认 `ver == 3`；遇到其它版本会明确报错，而不是静默失败或崩溃

## 🖥️ 图形界面版本 (GUI)

适用于 Windows 10/11，提供简洁的图形操作界面。

### 特点

* **三个并列功能**：加密文件 / 解密文件 / **安全删除**
* **设置面板**（右上角齿轮按钮）
  * 语言：中文 / English
  * 主题：跟随系统 / 浅色 / 深色
  * 输出文件位置：源文件同目录 / 指定目录 / 每次都询问
  * **安全删除覆写次数：1 / 2 / 3 次**（分段选择，见下方说明）
  * 完成后：关闭窗口 / 弹窗提示
  * 加密强度：快速 / 标准 / 安全 / 极强
  * **加/解密后保留源文件（不删除）**：勾选后加解密都不删除原文件
  * **禁用诱饵文件**：勾选后只写一个槽，文件体积约 1 倍（默认 2 倍），代价是体积会暴露"没有诱饵"
* **现代 UI**：WinUI 3 风格自绘界面，圆角控件、悬停与进度动画、深色模式
* **密码强度提示**：实时彩色分级（很弱 / 一般 / 良好 / 很强）
* **完全便携**：单 EXE 文件，无需额外 DLL

> 设置保存在注册表 `HKCU\Software\FileEncryptor`。

### 安全删除

独立的删除功能，与加密/解密并列。四种入口：

| 入口 | 操作 |
|---|---|
| 主界面按钮 | 点「安全删除」→ 多选文件 → 二次确认 |
| 拖放 | 把文件拖到「安全删除」按钮上，按钮变红并显示「松开删除」→ 松手 → 二次确认 |
| 资源管理器右键菜单 | 选中文件 → 右键 → **用FileEncryptor安全删除** |
| 命令行 | `enc --delete <文件...>`（可一次多个，覆写次数用 `-w` 指定） |

```bat
:: 覆写 3 次后删除一个文件
enc --delete secret.txt

:: 一次删多个
enc --delete a.txt b.txt c.txt

:: 直接删除，不做覆写（更快，但不可恢复性更弱）
enc --delete temp.log -w 0
```

* **GUI 的所有删除操作开始前都会弹出二次确认框**，写明文件数量与覆写次数，不可撤销
  （命令行版本按惯例不弹确认，直接执行）
* 复用与加解密相同的任务队列，因此**批量处理、进度条、后台托盘、队列计数**全部具备
* 覆写次数取自设置面板的「安全删除覆写次数」（1-3）；命令行用 `-w`（0-10）

> ⚠️ **关于覆写次数**：输入大于 3 时会提示"注意：覆写次数过多可能减少磁盘使用寿命，并降低删除速度"。
> 这**不是吓唬人**——多次全盘覆写确实会增加 SSD 写入量。
>
> ⚠️ **关于覆写的实际效果**：在全盘加密（BitLocker）、SSD 磨损均衡、写时复制文件系统
> （ReFS / Btrfs / ZFS）或云同步目录下，覆写**不保证**能抹掉原始数据——这些机制会把新数据写到别处，
> 旧块仍可能残留。覆写只是"尽力而为"，**不是物理销毁**。

### 资源管理器右键菜单

程序每次启动时会自动把两个菜单项注册到 `HKCU\Software\Classes\*\shell`（**不需要管理员权限**）：

| 菜单项 | 实际执行 |
|---|---|
| 用FileEncryptor加密 | `FileEncryptor.exe --encrypt "%1"` |
| 用FileEncryptor安全删除 | `FileEncryptor.exe --secure-delete "%1"` |

* 采用 `MultiSelectModel=Player`：多选时资源管理器会为**每个文件各启动一个进程**，
  程序通过**单实例转发**把这些文件汇总到已运行的窗口，所以多选也是**一批**处理
* 菜单项标题跟随程序语言设置，每次启动都会重写（exe 被移动过也能自动纠正）
* **可以在设置里关闭**：取消勾选「在资源管理器右键菜单中显示」并确定，程序会**立即删除**已注册的菜单项（重新勾选即恢复）
* 想手工清理时也可以直接删注册表：

```bat
reg delete "HKCU\Software\Classes\*\shell\FileEncryptor.Encrypt" /f
reg delete "HKCU\Software\Classes\*\shell\FileEncryptor.SecureDelete" /f
```

> ⚠️ **Windows 11 用户请注意**：菜单项出现在**经典（旧版）右键菜单**里，
> 需要先点「显示更多选项」或按 `Shift+F10` 才能看到，**不会出现在 Win11 的新版紧凑菜单中**。
> 进入新版菜单要求把外壳扩展打包成 **MSIX / sparse package** 并**代码签名**，
> 属于独立工程（需要签名证书），当前版本未做。

## ⌨️ 命令行版本 (CLI)

适用于 Windows，适合服务器、远程环境或自动化脚本。

### 编译

**Windows (MSVC，密码学用系统 CNG，无需第三方库)**

```bat
cl /EHsc /std:c++17 /MT /O2 /GL /DNOMINMAX /utf-8 ^
   enc.cpp file_crypto.cpp /Fe"enc.exe" ^
   /link /LTCG ^
   ws2_32.lib gdi32.lib crypt32.lib advapi32.lib user32.lib
```

> `/utf-8` 建议保留：源码是 UTF-8（带 BOM），源文件本身已能保证被正确识别，
> 但 MSVC 的“执行字符集”默认跟随系统 ANSI 代码页，加上 `/utf-8` 才能让中文
> 提示信息在任何区域设置下都固定为 UTF-8。
> 源码内也用 `#pragma execution_character_set("utf-8")` 做了兜底，漏加该参数也不会乱码。

> **依赖**：无需任何第三方库——密码学（AES-256-GCM / PBKDF2-HMAC-SHA256 / HMAC-SHA256 / 随机数）
> 全部使用 Windows 自带的 CNG（bcrypt），编译只需 Windows SDK。
> Windows 专有库（`ws2_32` / `gdi32` / `crypt32` / `advapi32` / `user32`）由系统提供，无需额外安装。

### 中文与路径编码

* 源码为 **UTF-8（带 BOM）**，在 ANSI 代码页不是 UTF-8 的机器（例如默认的简体中文 Windows，代码页 936）上同样能正确编译
* Windows 下程序内部统一使用 **UTF-8** 表示路径，调用文件 API 前显式转换为 UTF-16，
  因此**中文文件名、中文输出目录在任何区域设置下都能正常工作**
* 启动时会把控制台输出代码页临时切到 UTF-8（退出时还原），保证中文提示不会显示为乱码

### 使用方法

```bash
# 交互式加密（会提示输入密码并确认）
enc -i 文件路径

# 命令行直接提供密码（加密，会二次确认）
enc -i 文件路径 -p 你的密码

# 指定加密强度（fast | standard | secure | extreme，默认 standard）
enc -i 文件路径 -p 你的密码 -s extreme

# 输出到指定目录（加密后在 D:\Encrypted 下生成 文件路径.enc）
enc -i 文件路径 -p 你的密码 -o D:\Encrypted

# 保留源文件（加密后不删除原文件）
enc -i 文件路径 -p 你的密码 -k

# 交互式解密
enc -d -i 文件路径.enc

# 命令行直接提供密码（解密，适合批量）
enc -d -i 文件路径.enc -p 你的密码

# 解密到指定目录，并保留加密文件
enc -d -i 文件路径.enc -p 你的密码 -o D:\Decrypted -k
```

### 参数说明

| 参数 | 说明 |
|---|---|
| `-e` / `-d` | 加密 / 解密模式（必填其一） |
| `-i <文件>` | 输入文件路径（必填） |
| `-o <目录>` | 输出目录，默认为输入文件所在目录。目录必须已存在 |
| `-p <密码>` | 密码；不提供则交互式输入（输入时不回显） |
| `-s <强度>` | `fast` / `standard` / `secure` / `extreme`，默认 `standard` |
| `-w <次数>` | 源文件处理：`0` = **保留源文件**（等同 `-k`），`1` / `3` = 删除前覆写次数，默认 `3` |
| `-k` / `--keep` | 保留源文件（加密时）/ 加密文件（解密时），不做任何删除 |
| `-t <次数>` | **启用防暴力破解**：允许的错误尝试次数（1-9999）。不指定则不启用 |
| `-x <动作>` | 次数用尽后：`delete` = 永久删除文件（默认），`lock` = 禁止解密一段时间 |
| `-l <天数>` | `lock` 模式下的锁定时长（0-3650，默认 7） |
| `--decoy <文件>` | **可否认加密**：指定诱饵文件（受胁迫时用来顶替真实文件） |
| `--decoy-pass <密码>` | **可否认加密**：假密码，用它能解出诱饵文件 |
| `--no-decoy` | 只写一个槽，文件体积约 1 倍（默认 2 倍）。代价是体积会暴露"没有诱饵" |
| `--delete` / `-D <文件...>` | **安全删除**：只删文件，不加密也不解密；可一次给多个文件，覆写次数由 `-w` 决定 |
| `-h` / `--help` | 显示帮助 |

> 输出文件名自动推导：加密在原名后追加 `.enc`，解密去掉 `.enc`。
>
> 与 GUI 版一致：`-w 0` 对应设置里的「加密后保留源文件」，含义是**保留源文件**（不删除），而不是直接删除。
>
> `--decoy` 与 `--decoy-pass` **必须同时提供**，且假密码不能与真密码相同；
> 假密码只用于「被胁迫时交出去」，本身不影响真实内容的安全性。
>
> `--no-decoy` 会**牺牲不可否认性**（文件大小本身就会暴露没有诱饵），
> 只有在确定不需要诱饵功能时才建议使用。

### 防暴力破解

加密时启用，策略会写进文件头，**解密方无需任何设置即自动执行**（GUI 与 CLI 通用）。

* **GUI**：在「设置密码」框里勾选 `输入错误密码 [N] 次后`，并选择 `永久删除文件` 或
  `禁止解密`（选后者时可再填锁定时长 N 天）。**默认不勾选。**
* **CLI**：用 `-t` 启用：

```bash
# 错 3 次即永久删除文件
enc -i secret.txt -p mypass -t 3

# 错 5 次则禁止解密 7 天
enc -i secret.txt -p mypass -t 5 -x lock -l 7
```

* **GUI 解密**时，「输入密码」框下方会用红字显示 `还能尝试 X 次`；输错会扣减并重新弹框
* **CLI 解密**时，交互式提示为 `输入密码（还能尝试 X 次）`；用 `-p` 则失败时输出 `还可尝试 X 次`
* 处于锁定期时，**即使密码正确也会被拒绝**，并提示剩余锁定时长
* 锁定期结束后首次解密会自动把次数重置为初始值

批量解密时，**每个文件独立校验与重试**（"每个文件单独输入密码"分支）；
若选择"所有文件使用相同密码"，则只以**第一个文件**为准做校验与重试，
其余文件若密码不同，会在实际解密失败时各自扣减次数。

#### ⚠️ 这个机制的能力边界（务必了解）

剩余次数与锁定时间**必须能在不知道正确密码的情况下被改写**（否则输错一次文件就永久打不开了），
因此它们**无法被密码学认证**，任何人都可以：

* **在尝试前先复制一份 `.enc`，每次失败后还原副本** —— 计数器永远不会归零
* 直接用十六进制编辑器把剩余次数改回初始值、把锁定时间清零

所以它是一道**有效的威慑与减速带**，但**不能对抗有意为之的攻击者**。请勿把它当作可靠的保密手段。

文件头的其他部分（salt、IV、迭代次数、以及**保护策略本身**）已纳入 GCM 的 AAD 认证，
因此攻击者**无法通过篡改文件头「关掉保护」**——那样改动会导致认证失败，文件同样解不开。

> 「永久删除文件」不可逆：若自己忘记密码并连续输错达到上限，文件将被真的删除，无法恢复。

### 可否认加密（诱饵文件）

加密时可以额外指定一个**诱饵文件**和一个**假密码**。被胁迫时交出假密码，
对方解出来的就是那个诱饵文件；真密码解出真实内容。

* **CLI**：`--decoy <诱饵文件> --decoy-pass <假密码>`
* **GUI**：设置密码时勾选「使用诱饵文件（可否认加密）」，随后选择诱饵文件并设置假密码
  （仅单文件加密时提供；批量时为每个文件各配一份诱饵交互过重）

#### ⚠️ 这个机制的能力边界（务必了解）

**能做到**：

* 被胁迫交出密码时，交出的密码解出的是诱饵文件，真实内容不暴露
* 单看文件本身，**无法判断两个槽哪个是真的，也无法判断是否存在诱饵**
  —— 无论有没有配诱饵，文件结构完全一致

**做不到**：

* **抗"存在性"否认能力有限**：文件体积约为明文的 2 倍，结构上确实存在两段密文。
  懂行的人可以据此推断「这里可能藏了第二份内容」。
  真正的隐藏卷是把第二份藏进未分配空间，**本方案不是隐藏卷**。

> **如果确定不需要诱饵功能**，可以在设置里勾选「禁用诱饵文件」（CLI 用 `--no-decoy`）：
> 此时只写一个槽，**文件体积回到约 1 倍**。
> 代价正是上面第一条 —— 单槽文件恰好是 1 倍、双槽是 2 倍，
> **文件大小本身就会暴露"这个文件没有诱饵"**，也就是拿"不可区分性"换"体积"。
> 勾选后密码框里也不再显示诱饵选项。
* 若攻击者**同时掌握两个密码**，可以分别解出两份内容
* 无法抵抗持续性的胁迫（rubber-hose）
* 与防暴力破解共用同一份计数：胁迫者若输错假密码同样会消耗次数，
  配置了「次数用尽永久删除」时存在误删风险
### 批量处理示例

```bat
:: Windows 批处理 (CMD)：批量解密到指定目录
for %f in (*.enc) do enc -d -i "%f" -p mypass -o D:\Decrypted
```

```powershell
# PowerShell：批量加密并保留源文件
Get-ChildItem *.txt | ForEach-Object { .\enc.exe -i $_.FullName -p mypass -o .\encrypted -k }
```

## 🔒 安全说明

* 命令行版本与图形界面版本使用**完全相同的加密算法与文件格式**（AES-256-GCM + PBKDF2），加密后的文件可以在两个版本之间**互相解密**
* **删除策略**（GUI 在设置中调整，CLI 用 `-k` / `-w` 控制）
  * 加密：源文件含明文，覆写 1 次或 3 次后删除；选择「禁用」、加 `-k` 或 `-w 0` 则**保留源文件**
  * 解密：加密文件本身是密文、不含明文残留，因此**不做覆写**，直接删除；选择「禁用」、加 `-k` 或 `-w 0` 则**保留**
* 对于 SSD、云同步文件夹等特殊存储介质，覆写无法保证 100% 不可恢复
* 建议在本地、非同步目录中使用，并自行评估安全风险
* **请妥善保管密码，丢失后将无法解密**（AES-256-GCM 无后门、无恢复机制）
